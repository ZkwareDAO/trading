# Buddy 应用「CTA 交易工作台」配置草稿 v0.1

> 依据 WorkBuddy 开放平台 Buddy 应用文档（5 个配置模块）编写。**本文为草稿**：
> 带 `(待确认)` 的字段需要登录开放平台后按实际表单选项核定；标注 ⚠️ 的项涉及合规敏感点。
> 配置流程提示：允许跳步骤编辑；每次退出配置前用平台的导出配置功能备份 JSON。

## 模块 1：创建应用（身份信息）

| 配置项 | 值 | 说明 |
|---|---|---|
| 应用 ID | 系统自动生成 | 不可修改 |
| 应用头像 | （待设计） | 建议 256×256；若平台要求走 icon 规范则按 16px/1.2px 线宽规范另出一套 |
| 应用名称 | CTA 交易工作台 | ⚠️ 避免出现"保证收益""稳赚"类表述 |
| 应用简介 | CTA 量化策略研究工作台：策略开发、回测探索、每日复盘、部署上线，一条链路闭环。 | 定位为**研究工具**，⚠️ 不出现"代客理财""投资建议""自动盈利" |
| 授权列表 | 暂无（v0.1 不接 OAuth） | 四个 skill 均为 Bash 脚本形态，无第三方 OAuth 依赖 |
| 授权回调 URL | 空 | 同上 |
| 可信 Origin | 空 | 同上 |

创建后立即保存 Client Secret（仅展示一次）。

## 模块 2：首页配置

### 首页标题（Slogan）

```
从一个策略想法，到一条回测曲线
```

备选：`策略开发 · 回测探索 · 每日复盘，一个工作台全搞定`

### 工作模式（建议 3–5 个，本方案 3 个）

**模式 1：策略开发模式**

| 项 | 配置 |
|---|---|
| System Prompt | 你是 CTA 量化策略开发专家。当前处于策略开发模式：用户给出策略想法（如"双均线金叉做多、死叉平仓"），你按 trading-dev skill 的流程执行——环境预检 → 项目脚手架 → 策略编码 → 回测验证 → benchmark 报告。回测不达标时自动回到策略修改环节迭代（最多 5 轮）。术语规范：使用 Sharpe/MaxDD/年化/胜率等标准指标名；所有结论必须引用回测数据，禁止无数据支撑的收益断言。⚠️ 输出末尾固定附带："回测结果不代表未来收益，不构成投资建议。" |
| 绑定 Skill | trading-dev |

**模式 2：回测研究模式**

| 项 | 配置 |
|---|---|
| System Prompt | 你是量化回测研究专家。当前处于回测研究模式：帮助用户做策略横向对比——指定代币、策略、时间范围，拉取策略代码、校验配置、批量回测、输出对比报告。原则：参数不全时逐步引导补齐，不报错甩给用户。输出对比表必须包含每种组合的核心指标（年化、Sharpe、MaxDD、交易次数）。⚠️ 同样固定附带回测免责声明。 |
| 绑定 Skill | trading-discovery, trading-replay |

**模式 3：部署运维模式**

| 项 | 配置 |
|---|---|
| System Prompt | 你是策略部署工程师。当前处于部署运维模式：辅助用户完成策略上线路径——拉取策略代码、分析配置结构、验证数据流、准备 K 线数据、生成运行时配置、启动策略。涉及生产环境操作时，每一步执行前必须向用户确认。⚠️ 该模式仅指导与编排，不代用户操作实盘账户、不接入交易所下单接口。 |
| 绑定 Skill | trading-deploy |

> ⚠️ 合规提示：模式 3 是整个应用最敏感的部分。若审核阶段被质疑，备选方案是砍掉模式 3，把 deploy 从市场配置中摘除，应用只保留研究侧（模式 1/2）。

### 场景胶囊（输入框上方快捷提示词）

| # | 胶囊文案 | 预绑定 |
|---|---|---|
| 1 | 开发一个双均线策略 | 模式 1 |
| 2 | 用一句话描述你的策略想法，我来跑通全流程 | 模式 1 |
| 3 | 对比 EMA 和 RSI 在 BTCUSDT 上的表现 | 模式 2 |
| 4 | 探索回测：多代币 × 多策略批量对比 | 模式 2 |
| 5 | 复盘昨天：实盘信号 vs 回测信号 | 模式 2 |
| 6 | 部署一个已验证的策略到运行环境 | 模式 3 |

### 内置连接器

v0.1 不配置（四个 skill 均为本地 Bash 执行，无 OAuth MCP 依赖）。
后续演进方向 `(待确认)`：若批量回测需要常驻服务，做一个回测引擎 MCP（OAuth 认证）作为内置连接器，模式 2 提速。

## 模块 3：市场配置

| 板块 | 配置 |
|---|---|
| 专家 | v0.1 不启用专家/专家团（待有领域专家资产后补充） |
| 技能 | 勾选已上架的 trading-dev、trading-discovery（+ 视审核结果的 trading-replay / trading-deploy）。分类标签建议：`策略开发`、`回测研究` |
| 连接器 | v0.1 不配置 |
| 精选场景 | 可暂不开启；开启时关联「策略开发模式」+ 场景胶囊 1，背景图按 1000×910 双套（日/夜）规范另出 |

依赖关系：**本模块要求四个技能已在技能市场上架**。若技能尚未过审，Buddy 应用先以仅含模式 1/2 的最小版本提交，技能过审后再补勾选（修改需重新提审）。

| 配置项 | 值 |

| 输入框占位符（英文） | `Describe your strategy idea, or try "compare EMA vs RSI"` |
| 模型勾选 | 默认跟随 `(待确认)`——量化场景建议优先勾选推理能力强的模型；登录后按模型池实际清单勾选 |
| 默认模型 | 推理能力最强的一款（拖到首位） |

## 模块 5：预览调试

1. 全部模块配置完成后，通过预览链接下载对应版本 WorkBuddy 端，打开预览态。
2. 验证清单：
   - [ ] 三个工作模式切换正常，System Prompt 生效（问一个模式内问题验证话术）
   - [ ] 六个场景胶囊点击后正确叠加对应模式
   - [ ] 技能调用可达：在预览态让 AI 实际调一次 trading-dev（环境预检那步能跑通即可）
   - [ ] 免责声明出现在回测类输出末尾
   - [ ] 中英文占位符切换
3. 导出配置 JSON 存档（命名建议 `buddy-cta-workbench-0.1.0.json`）。
4. 提交配置审核。

## 发布路径与后续

```
创建应用 → 创建审核（通过后转草稿）→ 分模块配置 → 预览调试 → 配置审核 → 发布上线
```

- 后续任何变更（含勾选新技能）→ 修改后重新提审。
- 企业内测分发：应用上架且发布范围勾选企业后，走企业单管理（企业 ID + 授权模式 + 时长 ≤1 年；同一应用对同一企业目前只能发一次单，谨慎创建）。
- 迭代路线：v0.1 最小可用（3 模式 + 2 技能）→ 根据运营数据（T+1，看安装量/调用量/7 日留存）→ v0.2 考虑 MCP 回测引擎连接器与专家资产。
